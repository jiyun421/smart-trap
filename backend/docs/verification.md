# 구현 및 검증 현황

| 단계 | 구현 | 확인 결과 |
| --- | --- | --- |
| 1. 개발 환경 | 가상환경, 의존성, 환경 변수, Git 제외 규칙 | Windows, Python 3.15.2, Flask 3.1.3에서 가상환경의 의존성과 Flask 개발 서버 기동 확인 |
| 2. 서버 | Flask 앱 팩터리와 Blueprint, DB 헬스 체크, 역할별 인증 | Flask 테스트 클라이언트로 헬스 체크와 인증 응답 확인 |
| 3. SQLite | WAL 마이그레이션, 인덱스, 트랩·위치·설치 등록 CLI | SQLite 3.53.4에서 무결성 확인. Flask CLI로 초기화, 등록, 재배치 확인 |
| 4. ESP32 수신 | 이벤트 검증, 중복 처리, 역순 수신, 기존 설치 지연 수신 | 정상·오류·동시 재전송, DB 잠금, 재배치 후 지연 수신, 역순 방문 처리 확인 |
| 5. 조회와 CSV | 상태, 이력, 일자 집계, 범위 제한 CSV 스트리밍 | 상태와 미끼 임계값, 서울 시간 날짜 경계, CSV 내용과 다운로드 중단 시 DB 연결 해제 확인 |
| 6. 추천 연동 | 실행·후보 저장, 최신 실행, 자료 부족 상태 | 모의 ESP32→CSV→모의 PC 추천 등록→최신 추천 조회 통과 |
| 7. 배포 | Gunicorn, systemd, 정적 파일, 백업·복원 문서 | 테스트용 정적 빌드 제공 확인. Pi의 SSH·LAN·ESP32, 실제 대시보드 및 서비스 재부팅 후 DB 유지는 현장 검증 대상 |

`python -m unittest discover -s tests -v`로 통합 테스트 14개를 실행했으며 모두 통과했습니다. Flask 개발 서버는 기동했고, 작업 환경의 소켓 연결 권한 제한으로 별도 HTTP 클라이언트의 TCP 접속 확인은 보류했습니다.

7단계 코드는 한 프로젝트에 통합되어 있습니다. 대상 Git 저장소와 브랜치가 확인되면 그 저장소의 기존 인터페이스와 비교하고 실제 병합을 수행할 수 있습니다.

팀 연동 전에 실제 트랩·설치 ID, 종 코드 목록, 보고 간격, 포획 확인 근거를 ESP32 담당자와 확인합니다. PC 담당자와는 후보 위치 ID, 예측 종류와 점수 해석, 조회용 인증, 대시보드 빌드 경로를 확인합니다. 현재 코드는 [API 계약서](api.md)의 기본값을 적용합니다.
